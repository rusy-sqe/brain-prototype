SQE Suite DS — Master Gap Analysis

A single view across the three redesign audits run against this design system this cycle — CognifAI, M&A Brain and SQE Horizon 2.0. Individually, each names what its app needs and the DS lacks. Compiled together, the value is different: the same handful of components recur across all three unrelated products, which means building them once in the DS unblocks three roadmaps at once, rather than three teams each re-solving dialog, table and form primitives on their own.

03What's unique to each app — and worth designing suite-wide anyway

These didn't recur because each app's domain is genuinely distinct — but two of the three domains (AI-mediated assessment, AI agent/copilot) are directions the rest of the suite is visibly heading, so the source audits flag them as primitives to design once, not one-off features.

CognifAI

Proctored AI-assessment for candidates

  • Camera/permission gate + calibration orb
  • Phase stepper with live countdown
  • Case brief panel + deck-builder field set
  • Integrity flag & verdict badges
  • 5-dimension scorecard

M&A Brain

AI copilot for deal sourcing & fund management

  • Chat bubble, composer & AI markdown prose
  • Reasoning / step-trace panel
  • Agent action card (approve/reject proposal)
  • AI opinion/confidence display
  • Relationship graph & flow canvas

SQE Horizon 2.0

Mining ops forecasting & admin console

  • Forecast-vs-actual chart with crosshair/pick
  • Map marker/pin, geocode & coordinate picker
  • Dark basemap tiles
  • Product tour / coachmark
  • Appearance (theme) picker

The chat/agent overlap is the one to watch. CognifAI's AI-chat and M&A's copilot are independently-arrived-at versions of the same thing: a message bubble, a composer, and a structured "AI proposes, human decides" card. That's two of three apps converging on a pattern language the DS doesn't have yet — treat it as a Tier-1 candidate for the next audit cycle, not a one-off per product.

05Unified build order

One sequence, merged from all three roadmaps, so a single DS team effort clears the ground for all three redesigns rather than optimizing for one.

  1. Foundations

    Move dark mode to a class/attribute scope, purge pinned ramp stops, add the scrim/chart-series/threshold tokens, unpin the display font, ship the Tailwind/shadcn token bridge for M&A. Nothing below should start before this.

  2. Form & input family

    Text input, form field wrapper, textarea, select, combobox, search input, file dropzone. Retires the largest source of per-app "app-input"-style patching and unblocks every overlay that contains a form.

  3. Overlay layer

    Popover, dropdown menu, dialog/modal, confirm dialog, sheet/drawer, toast queue, skeleton, collapsible. This is the single largest recurring gap across all three audits.

  4. Table & app shell

    DataTable with cell vocabulary, table toolbar, bulk-selection bar, pagination, empty states, KPI card, app shell, behavioural sidebar, account menu, breadcrumb. Validate on each app's densest screen.

  5. AI & agent primitives

    Chat message bubble, composer, AI markdown prose, reasoning trace, agent action card, confidence/opinion display, job/run status. Design as suite-wide assessment/copilot primitives — CognifAI and M&A both need this shape now, and it's the direction the rest of the suite is heading.

  6. Domain specialty tracks

    Assessment/proctoring shell (CognifAI), map/forecast + relationship graph (Horizon, M&A), document/file review surfaces (M&A). Run in parallel once Phase 4 primitives exist to build on.

  7. Templates & long tail

    Auth template, settings template, product tour, theme picker, mobile shell, marketing/landing sections. Publish as templates/ starting points so the next suite product begins ahead of where these three started.
